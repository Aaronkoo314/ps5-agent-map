          Problem Set 5 · AK

          My agent card

          My agent card | Daily Settlement Logger | finished Sun 18 Oct 2026, 01:26 SGT
1. The job: After each trading day, it records that day's settlement (positions closed, wins and losses, net P/L, deposits and withdrawals, opening and closing balance) as one row in a Google Sheet, for a retail trader (me) who reviews performance.
2. The trigger: A new email in my Gmail sent to my +settle address with "Daily Settlement" in the subject, which my MT5 trading terminal sends when I run its DailySettlement script for a day.
3. The tools: Gmail, New Email Matching Search (the trigger, read only); Google Sheets, Create Spreadsheet Row (one sheet). Outside Zapier, the MT5 script only reads the account history and sends one email.
4. It must never: Act on the trading account. The Zap is connected only to Gmail and one Google Sheet, and the MT5 script contains no order functions.
5. Where a person checks: I read the new row the morning after each trading day, and once a week I compare one day's row with the MT5 History tab.

          Problem Set 5 · Step 2

          Tricky case: settling the same day twice

          The test: run the MT5 script for 16 Oct a second time, as could happen by accident in daily use. 16 Oct was already logged once, at 17:19 SGT.

          My prediction, recorded on Sun 18 Oct 2026 at 17:55 SGT, before the run:

          I expect nothing to go wrong. Settling 16 Oct a second time should leave the agent and the sheet working normally.

          What happened (Sun 18 Oct, 17:58 SGT)

          The Zap itself worked: Zap history shows a successful run, and Log gained a second 16 Oct row. The sheet did not: the Settlement tab showed 16 Oct twice.

          • P/L since first row counted the +440.93 twice: 468.40 instead of 27.47.
          • Balance check marked the duplicate row CHECK, because its opening balance (1864.14) is not the previous row's closing balance (2305.07). But the word was in very faint grey and easy to miss.
          • Total P/L stayed right at 1305.07, because it is worked out from the balance.

          So my prediction was wrong. The agent did its job; the sheet assumed each day arrives only once.

          The fix

          A free-plan Zap cannot look for an existing row before adding one (that takes a second step), and Log should keep every email as the full record. So the fix is in the Settlement tab: its formula now sorts the days by date and keeps one row per day. I also made CHECK show in bold red. Claude wrote the new formula; I applied it in the sheet and tested it.

          =SORTN(ARRAYFORMULA(IFERROR(SPLIT(REGEXEXTRACT(FILTER(Log!C2:C,Log!C2:C<>""),"CSV: ([^\r\n]+)"),";"),"no CSV line")),9^9,2,1,TRUE)

          Rerun (18:02 SGT)

          I settled 16 Oct a third time. Zap history shows another successful run and Log now holds three 16 Oct rows, but Settlement lists 16 Oct once: P/L since first row is back to 27.47, Balance check reads OK on every row, and Total P/L is 1305.07.
